# Codex review — F2 pruners (median + asha + architecture)

**Date:** 2026-07-10 · **Reviewer:** `codex exec` (codex-cli 0.144.1, reasoning_effort=medium, read-only).
**Disposition:** 1 Blocker, 3 Major, 3 Minor — all applied. Terminal-state lifecycle enforced (pruned/failed/completed are terminal; only idempotent same-status re-report allowed); true 50th-pct median; finite-score validation on tell_intermediate/tell_result; centralized pruner-kind validation in make_optimizer; one-value-per-step (update-in-place); ASHA reduction_factor documented as fixed-at-3 + ties-survive. +2 regression tests (lifecycle, invalid-pruner/NaN).

---

**Blocker**
1. Terminal state is not terminal. `tell_intermediate()` can mark a trial `N4M_TRIAL_PRUNED`, but later `tell()`/`tell_result(COMPLETED)` blindly overwrites status and score, making the pruned trial eligible for `best()` because `best()` only filters for `COMPLETED + has_score`. See [optimizer.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/optimizer.cpp:321), [optimizer.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/optimizer.cpp:338), [optimizer.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/optimizer.cpp:342), [optimizer.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/optimizer.cpp:351), [c_api_optimization.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/c_api/c_api_optimization.cpp:416). Fix: enforce lifecycle transitions; only `RUNNING` accepts intermediates or terminal results, optionally allow idempotent `tell_result(PRUNED)` after auto-prune to set duration/error, and reject `COMPLETED` after `PRUNED/FAILED`.

**Major**
2. Median uses the upper middle element, not the documented/Optuna 50th-percentile median. Code uses `peers[peers.size() / 2]`, and the test blesses `median(1,2)=2.0`, while docs claim Optuna MedianPruner semantics. This is direction-asymmetric: for peers `[1,3]`, score `2.5` is kept for minimize but pruned for maximize under the same threshold. See [pruners.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/pruners.cpp:34), [test_optimization.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/tests/test_optimization.cpp:489), [median_pruner.md](/home/delete/nirs4all/_worktrees/native-hpo-phase1/docs/methods/median_pruner.md:28). Fix: compute the true median for even `n`, or explicitly document/test “upper median” and drop the Optuna parity claim. Strict worse-than comparison itself is the right tie boundary.

3. Non-finite scores are accepted into pruner state. `tell_intermediate()` appends `score` without validation, then median sorts peer doubles; NaN makes ordering/decisions ill-defined and can violate `std::sort`’s comparator assumptions. See [optimizer.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/optimizer.cpp:334), [optimizer.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/optimizer.cpp:338), [pruners.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/pruners.cpp:34). Fix: reject non-finite intermediate/result scores at the C/core boundary or define a specific NaN policy before storing.

4. Pruner factory validation is split and can silently degrade invalid pruners to `none`. `make_optimizer()` rejects only `HYPERBAND/RACING`; the constructor then calls `make_pruner(opts, nullptr)` and ignores the `NOT_IMPLEMENTED` status. Out-of-range `opts.pruner` therefore creates an optimizer with `pruner_ == nullptr`. See [optimizer.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/optimizer.cpp:60), [optimizer.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/optimizer.cpp:364), [pruners.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/pruners.cpp:75). Fix: centralize pruner validation in `make_optimizer()` or pass a validated `Pruner` into the constructor; test `HYPERBAND`, `RACING`, and invalid enum values.

**Minor**
5. Duplicate reports for the same trial/step use stale peer values. Intermediates are append-only, but peer lookup scans forward and breaks on the first matching step. See [optimizer.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/optimizer.cpp:338), [pruners.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/pruners.cpp:25), [pruners.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/pruners.cpp:47). Fix: reject duplicate `(trial, step)` reports, update the existing value, or search from the back for the latest value.

6. ASHA tie semantics are implicit and can exceed the advertised top-`1/reduction_factor` quota. The rule counts only strictly better peers, so all ties at the cutoff survive. See [pruners.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/pruners.cpp:58), [asha.md](/home/delete/nirs4all/_worktrees/native-hpo-phase1/docs/methods/asha.md:5). Fix: document “ties survive” and add tie tests for both directions, or add deterministic tie-breaking if exact quota is required.

7. ASHA `reduction_factor` is fixed at `3` with no ABI option, while docs call it a default. See [pruners.cpp](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/src/core/optimization/pruners.cpp:73), [optimization.h](/home/delete/nirs4all/_worktrees/native-hpo-phase1/cpp/include/n4m/optimization.h:104), [asha.md](/home/delete/nirs4all/_worktrees/native-hpo-phase1/docs/methods/asha.md:7). Fix: either document it as fixed for F2 or consume reserved option space for pruner params before broader binding parity depends on it.

Top must-fix: lifecycle enforcement, median parity/definition, finite-score validation, and centralized pruner-kind validation.

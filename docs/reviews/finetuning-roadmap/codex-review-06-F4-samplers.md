# Codex review — F4 adaptive samplers (cmaes + tpe)

**Date:** 2026-07-10 · **Reviewer:** `codex exec` (read-only).
**Disposition:** 3 Blocker, 3 Major, 1 Minor. Applied: (B1) TPE requires n>=2 + non-degenerate split before activating (was OOB at n_startup=1); (B3) CMA-ES updates from COMPLETED+scored trials only, weights renormalised over n_use, skips update when none scored; (M4) CMA-ES step-size path from repaired step yw/sqrt(C) (not raw z) — consistent after box-clipping; (M5) CMA-ES restricted to CONTINUOUS axes (cont_axes_ map), other axes sampled independently; (M6) TPE categorical proposal sampled proportional to l/g (not argmax) — retry-safe, no livelock. Documented (consistent with ga/pso): (B2) hard mutex/requires/exclude handled via fitness for population/CMA samplers; (Minor7) TPE stepped-axis snap at decode.

---

1. **Blocker**: TPE can OOB when `n_startup_trials == 1`. With one history row, `n_good` is clamped down to `0`, then numeric sampling indexes `good[n_good - 1]`. See `cpp/src/core/optimization/tpe.cpp:49`, `cpp/src/core/optimization/tpe.cpp:56`, `cpp/src/core/optimization/tpe.cpp:58`, `cpp/src/core/optimization/tpe.cpp:73`. Fix: require `n >= 2` before TPE activates, or fallback random when `n_good <= 0 || n_good >= n`.

2. **Blocker**: CMA-ES bypasses constraints. `CmaEsSampler::sample()` calls `decode_candidate()` and returns true, while only the base sampler runs the retry loop and `constraints_ok()`. See `cpp/src/core/optimization/cma.cpp:169`, `cpp/src/core/optimization/cma.cpp:178`, `cpp/src/core/optimization/optimizer.cpp:183`, `cpp/src/core/optimization/optimizer.cpp:195`, `cpp/src/core/optimization/optimizer.cpp:266`. Fix: add constraint-aware repair/resampling for CMA candidates, or reject constrained spaces for CMA-ES.

3. **Blocker**: CMA-ES can update from pruned/failed/unscored trials. Generation readiness counts every non-running trial as resolved, but ranking gives unscored terminal trials `worst`; if fewer than `mu` completed trials exist, arbitrary unscored candidates enter the mean/covariance update. See `cpp/src/core/optimization/optimizer.cpp:372`, `cpp/src/core/optimization/cma.cpp:93`, `cpp/src/core/optimization/cma.cpp:103`, `cpp/src/core/optimization/cma.cpp:117`, `cpp/src/core/optimization/cma.cpp:149`. Fix: update only from completed scored trials; require at least `mu` scored trials, or define an explicit finite liar/pruned score policy.

4. **Major**: CMA-ES step-size path is inconsistent after box clipping. Candidates are clipped at sample time, `m_new`/`yw` are computed from clipped `pop_x`, but `p_sigma` uses raw `pop_z` under the comment that `C^-1/2*yw == zw`; that equality fails once clipping occurs. See `cpp/src/core/optimization/cma.cpp:75`, `cpp/src/core/optimization/cma.cpp:77`, `cpp/src/core/optimization/cma.cpp:121`, `cpp/src/core/optimization/cma.cpp:126`, `cpp/src/core/optimization/cma.cpp:128`, `cpp/src/core/optimization/cma.cpp:132`. Fix: compute the path from repaired steps, e.g. `yw[j] / sqrt(C_[j])`, or replace clipping with a proper bound transform/resampling policy.

5. **Major**: CMA-ES treats all search-space params as CMA coordinates, including categorical/ordinal/sorted-tuple and conditionally inactive params. That corrupts `P`, learning rates, paths, and sigma with axes that are bucketed, randomly generated, or later deactivated. See `cpp/src/core/optimization/cma.cpp:31`, `cpp/src/core/optimization/cma.cpp:73`, `cpp/src/core/optimization/optimizer.cpp:145`, `cpp/src/core/optimization/optimizer.cpp:166`, `cpp/src/core/optimization/optimizer.cpp:183`. Fix: maintain a CMA axis map for supported continuous axes only; sample unsupported/conditional axes independently, or reject mixed/conditional CMA spaces.

6. **Major**: TPE categorical override can livelock the base constraint retry loop. It deterministically picks the best ratio category every attempt; if that category combination violates a categorical constraint, all 200 retries can repeat the same invalid choice. See `cpp/src/core/optimization/tpe.cpp:119`, `cpp/src/core/optimization/tpe.cpp:125`, `cpp/src/core/optimization/tpe.cpp:130`, `cpp/src/core/optimization/optimizer.cpp:195`, `cpp/src/core/optimization/optimizer.cpp:265`. Fix: make categorical proposals retry-aware/stochastic, or exclude previously rejected categorical tuples before retrying.

7. **Minor**: TPE’s unit-space history ignores quantization when scoring stepped/int params. `numeric_from_unit()` snaps ints/steps, but `unit_from_numeric()` ignores `step`, and TPE maximizes `l/g` before decoding/snapping. See `cpp/src/core/optimization/optimizer.cpp:80`, `cpp/src/core/optimization/optimizer.cpp:86`, `cpp/src/core/optimization/optimizer.cpp:95`, `cpp/src/core/optimization/tpe.cpp:78`, `cpp/src/core/optimization/tpe.cpp:84`. Fix: model stepped/int axes as discrete grids, or snap candidates first and score the canonical snapped unit value.

Top must-fix: findings 1, 2, and 3.
